# RESTOPRO — Stage 1: Webhook Verification & Cryptographic Security

**Document Version:** 1.0.0  
**Implementation:** Express.js, Node.js `crypto` module, HMAC-SHA256  

---

## 1. Webhook Handshake (HTTP GET)

When a developer sets or edits the Webhook Callback URL in Meta's Developer Dashboard, Meta sends an HTTP GET request to verify server ownership.

### Protocol Specification
- **Endpoint:** `GET /api/webhook`
- **Query Parameters Sent by Meta:**
  - `hub.mode`: Set to `"subscribe"`.
  - `hub.verify_token`: The secret token entered in Meta's Dashboard.
  - `hub.challenge`: A random alphanumeric challenge string generated by Meta.
- **Expected Server Response:**
  - Status: `200 OK`
  - Body: The exact raw `hub.challenge` string as plain text (`text/plain` or raw buffer).

### Cryptographic Comparison
To prevent timing attacks, string comparison is performed in constant time using `crypto.timingSafeEqual`:

```javascript
const tokenBuffer = Buffer.from(token);
const expectedBuffer = Buffer.from(expectedToken);

const isMatch =
  tokenBuffer.length === expectedBuffer.length &&
  crypto.timingSafeEqual(tokenBuffer, expectedBuffer);
```

### Manual Testing with cURL
```bash
# Valid Request (Should return challenge string with HTTP 200)
curl -i "http://localhost:3000/api/webhook?hub.mode=subscribe&hub.verify_token=restopro_dev_verify_token_2026&hub.challenge=test_challenge_12345"

# Invalid Token (Should return HTTP 403 Forbidden)
curl -i "http://localhost:3000/api/webhook?hub.mode=subscribe&hub.verify_token=wrong_token&hub.challenge=test_challenge_12345"

# Missing Parameters (Should return HTTP 400 Bad Request)
curl -i "http://localhost:3000/api/webhook"
```

## 2. Request Signature Validation (HTTP POST)

Every incoming event from Meta includes a cryptographic signature in the HTTP request header:
`X-Hub-Signature-256: sha256=<hex_digest>`

This prevents request forgery, unauthorized callers, and man-in-the-middle tampering.

### The Raw Body Buffer Rule
Standard Express JSON parsers parse the request body into a JavaScript object. However, computing the HMAC signature over a re-stringified JSON object fails because JSON serialization changes whitespace, key ordering, and escaping.

Therefore, RESTOPRO retains the pristine raw `Buffer` directly from the incoming socket stream in `src/app.js`:

```javascript
app.use(express.json({
  verify: (req, res, buf) => {
    req.rawBody = buf; // Pristine, unparsed Buffer
  }
}));
```

### Verification Algorithm in `src/middleware/verifyWebhook.js`
1. Extract `x-hub-signature-256` header.
2. Verify format starts with `sha256=`.
3. Extract received hex digest.
4. Compute HMAC-SHA256:
   ```javascript
   const computedHash = crypto
     .createHmac('sha256', process.env.META_APP_SECRET)
     .update(req.rawBody)
     .digest('hex');
   ```
5. Compare digests using `crypto.timingSafeEqual`:
   ```javascript
   const receivedBuffer = Buffer.from(receivedHash, 'hex');
   const computedBuffer = Buffer.from(computedHash, 'hex');

   const isValid =
     receivedBuffer.length === computedBuffer.length &&
     crypto.timingSafeEqual(receivedBuffer, computedBuffer);
   ```

## 3. Failure Response Codes & Troubleshooting

| HTTP Code | Root Cause | Resolution |
| :--- | :--- | :--- |
| **400 Bad Request** | Missing `hub.mode` or malformed `x-hub-signature-256` header. | Verify query parameters or signature header prefix. |
| **401 Unauthorized** | Missing `x-hub-signature-256` header on POST request. | Caller is not sending Meta signature header. |
| **403 Forbidden** | Verification token mismatch or invalid HMAC signature. | Verify that `META_VERIFY_TOKEN` and `META_APP_SECRET` in `.env` match Meta Dashboard. |
| **500 Server Error** | `META_APP_SECRET` or `META_VERIFY_TOKEN` is unset in `.env`. | Configure required variables in `.env` and restart server. |
